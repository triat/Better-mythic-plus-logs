# Phase 2 (open signup, own WCL client, privacy, account deletion, health) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open the hosted instance to strangers safely: optional open signup (`BMPL_OPEN_SIGNUP=true`) with admin bans and an optional "must be in Discord server X" gate, a per-user Warcraft Logs client (pasted on a `/settings` page, encrypted at rest, verified with one PING, used for that member's lookups and analyses instead of the shared budget), a `/privacy` page and **Delete my account**, and a richer `GET /api/health` for the VPS monitoring.

**Architecture:** Config gains four optional variables (`BMPL_OPEN_SIGNUP`, `BMPL_DISCORD_GUILD_ID`, `BMPL_ENCRYPTION_KEY`, `BMPL_OPERATOR`); the schema gains `users.banned_at/banned_by` (additive `ALTER TABLE` guarded by `PRAGMA table_info`) and `user_wcl_clients`. Admission at the Discord callback becomes: banned → denied; guild required and not a member → denied; config admin → admin; invited → member; open signup → member (new accounts rate-limited per IP); else denied. The per-user WCL client is a small service (`src/hosted/wcl-clients.ts`) over an AES-256-GCM helper (`src/hosted/crypto.ts`, WebCrypto) and the `user_wcl_clients` repo; `src/wcl/auth.ts` caches one token per client id, and `src/wcl/client.ts` gets an AsyncLocalStorage "current WCL client" so `gql` — whoever calls it (`mplus.ts`, `enrich.ts`, `deepdive/run.ts`) — uses the member's credentials when the lookup/deep-dive handler runs inside `runWithWclClient`. Own-client responses never feed the shared meter (their `rateLimitData` goes to a per-user snapshot instead) and skip the quota gate. The front adds a `/settings` page (canvas layout **A**: two cards), a `/privacy` page, sign-in wording per mode, a "Settings" item + own-client quota line in the user menu, and Ban/Unban + "own client" in the admin Users section.

**Tech Stack:** Bun + `bun:sqlite` + WebCrypto (`crypto.subtle`), TypeScript strict, `bun test`; Vite 8 + React 19 in `web/`.

**Spec:** GitHub issue #11 (`gh issue view 11`), parent #1. Design: canvas https://claude.ai/artifact/3yUjZKgaQyHKebzyqcio5s page "Hosted", artboards `Phase2SettingsA.dc.html` (chosen: **A · full page**), `Phase2Details.dc.html` (verified-client state, typed-word delete confirmation, `/privacy` text, sign-in wording for open signup and the guild notice, admin Users with "own client" and Ban/Unban); sources in `docs/design/canvas/` (uncommitted until Task 6). Builds on #3 (auth, admission), #5 (meter / quota), #8 (admin page), #9 (validator, audit, rate limits), #10 (deploy `last-backup` marker). Monitoring ruling: the audit log + journald already are the "structured logs"; this plan extends `/api/health` and adds no Sentry client.

## Global Constraints

- **Never spend WCL points in tests or automatically.** The only new WCL call is the PING that verifies a member's *own* client on save / "Verify again" (≈ 0 pts, on *their* client), and it is injected (`ServeOptions.verifyWclClient`) so tests never reach `gql`; any test that could reach `gql` pins dummy `WCL_CLIENT_ID` / `WCL_CLIENT_SECRET`. Lookups and deep-dives through a member's own client are the same requests as today, just authenticated with their credentials.
- **Local mode untouched**: every feature here is hosted-only; local routes, CLI and the `/` screen stay pixel-identical (new CSS classes only: `.settings*`, `.field`, `.privacy*`, `.row-banned`).
- **Secrets never leave the server**: a client secret is written once (PUT), stored only as AES-256-GCM ciphertext (`v1.<iv b64>.<ciphertext+tag b64>`), never returned, never logged, never in an audit row; the client id is returned abbreviated (`a3f1…9c2e`, the existing `abbreviate` of `src/hosted/instance.ts`, exported). Without `BMPL_ENCRYPTION_KEY` the feature is off: `GET /api/me/wcl-client` → `{ ok: true, enabled: false, client: null }`, `PUT` → `503 { ok: false, error: "This instance does not store WCL clients (no BMPL_ENCRYPTION_KEY)" }`.
- **Own client = own budget**: a request that runs through a member's client is never charged to `usage_hourly`, never feeds `PointsMeter.observe`, and skips `QuotaGate.reserve`; its `rateLimitData` is kept in memory per user (`UserWclClients.observe`) and shown as "Your WCL client · 1 412 / 3 600 pts".
- **Admission order at `/auth/discord/callback`** (after identity): banned → `/?denied=banned` (audit `login_denied` reason `banned`); `discordGuildId` set and the account is not in that guild → `/?denied=guild` (reason `guild`); config admin → admin; invited → member; `openSignup` → member; else `/?denied=<discordId>` (reason `not invited`). A *new* account under open signup counts against `limits.signup` (5 per hour per IP): refused → `/?denied=rate` and audit `rate_limited`. Guild membership is read from `GET https://discord.com/api/users/@me/guilds` (scope `identify guilds` only when `BMPL_DISCORD_GUILD_ID` is set) and nothing from it is stored.
- **Ban**: `POST /api/admin/users/:id/ban` sets `banned_at/banned_by`, ends every session, and `resolveRequest` treats a banned user as anonymous; a banned user's rows stay until they delete the account (they cannot sign in to do so — the admin can delete them later; out of scope) or the admin unbans. Cannot ban yourself (400 "You cannot ban yourself") or a config admin (400 "Config admins cannot be banned"). Audit `user_ban` / `user_unban`.
- **Delete my account** (`DELETE /api/me`): audit `account_delete` first (`userId: null`, target `discord <id>`, detail `{ username }`), then `DELETE FROM users` (cascades: sessions, history, settings, usage, proposals, wcl client; `SET NULL`: approved shared entries, decided proposals, audit rows), clear the cookie, `{ ok: true }`. The front asks for the typed word `delete` (case-insensitive, trimmed) before calling.
- **Health** (hosted only): `GET /api/health` → `{ ok, version, uptimeS, db, hosted: true, users, sessions, wcl: { pointsSpentThisHour, limitPerHour, pointsResetIn } | null, backupAgeS: number | null, warnings: string[] }`; `warnings` never flips `ok` (the proxy must not flap); local mode keeps `{ ok, version, uptimeS, db }`.
- **New audit actions** (front `AUDIT_KIND_OF` mirrors): `account_delete`, `wcl_client_set`, `wcl_client_remove` → kind `login`; `user_ban`, `user_unban` → kind `admin`.
- **Rate limits**: `PUT /api/me/wcl-client` and `POST /api/me/wcl-client/verify` count against `limits.lookup` per user (each one is an outbound OAuth + PING); `limits.signup = { limit: 5, windowMs: 3_600_000 }` per IP, new accounts only.
- **English everywhere**; front strings from the canvas (Task 5 lists them verbatim).
- **Style**: 2 spaces, double quotes, trailing commas, `.ts`/`.tsx` extensions; `just check && bun test` green with `web/dist` absent at the end of every task.
- **Git**: `main` in place, explicit `git add` paths, never `biwaasham.json`, `defensives.json`, `evaluation.json`, `.env`, `bmpl.db*`, `web/dist`, `dist/`. Commit trailers as the session provides. Never run `just deploy*` or `deploy/bootstrap.sh`.

```ts
// AES-256-GCM over WebCrypto for the members' WCL client secrets (issue #11). Format: "v1.<iv b64>.<ct+tag b64>".
export const SEALED_PREFIX = "v1.";
const IV_BYTES = 12;
const importKey = (key: Uint8Array) => crypto.subtle.importKey("raw", key, "AES-GCM", false, ["encrypt", "decrypt"]);
const b64 = (bytes: ArrayBuffer | Uint8Array): string => Buffer.from(bytes instanceof Uint8Array ? bytes : new Uint8Array(bytes)).toString("base64");

export async function encrypt(key: Uint8Array, plaintext: string): Promise<string> {
  const iv = crypto.getRandomValues(new Uint8Array(IV_BYTES));
  const ct = await crypto.subtle.encrypt({ name: "AES-GCM", iv }, await importKey(key), new TextEncoder().encode(plaintext));
  return `${SEALED_PREFIX}${b64(iv)}.${b64(ct)}`;
}

/** null on any failure (wrong key, tampering, bad format): the caller treats it as "no usable secret". */
export async function decrypt(key: Uint8Array, sealed: string): Promise<string | null> {
  if (!sealed.startsWith(SEALED_PREFIX)) return null;
  const parts = sealed.slice(SEALED_PREFIX.length).split(".");
  if (parts.length !== 2) return null;
  try {
    const iv = Buffer.from(parts[0]!, "base64");
    const ct = Buffer.from(parts[1]!, "base64");
    if (iv.length !== IV_BYTES || ct.length === 0) return null;
    const plain = await crypto.subtle.decrypt({ name: "AES-GCM", iv }, await importKey(key), ct);
    return new TextDecoder().decode(plain);
  } catch {
    return null;
  }
}
```

```ts
async function handleHealth(sc: SharedContext): Promise<Response> {
  const base = { version: pkg.version as string, uptimeS: Math.round(process.uptime()) };
  let db: "ok" | "error" = "ok";
  try { (await getStore())._db.query("SELECT 1").get(); } catch { db = "error"; }
  if (!sc.runtime) return jsonResponse({ ok: db === "ok", ...base, db }, db === "ok" ? 200 : 503);
  const rt = sc.runtime;
  const now = Date.now();
  const snap = rt.meter.snapshot();
  const backupAt = lastBackupAt(dirname(sc.envPath));
  const backupAgeS = backupAt === null ? null : Math.max(0, Math.round((now - backupAt) / 1000));
  const warnings: string[] = [];
  if (backupAgeS === null) warnings.push("no backup marker");
  else if (backupAgeS > BACKUP_STALE_S) warnings.push(`last backup ${Math.round(backupAgeS / 3600)} h ago`);
  if (snap && now < snap.windowEnd && snap.limitPerHour - snap.pointsSpentThisHour < POINTS_FLOOR) warnings.push(`shared WCL budget under ${POINTS_FLOOR} pts`);
  return jsonResponse({
    ok: db === "ok", ...base, db, hosted: true,
    users: rt.db.users.count(), sessions: rt.db.sessions.countActive(now),
    wcl: snap ? { pointsSpentThisHour: snap.pointsSpentThisHour, limitPerHour: snap.limitPerHour, pointsResetIn: snap.pointsResetIn } : null,
    backupAgeS, warnings,
  }, db === "ok" ? 200 : 503);
}
```
