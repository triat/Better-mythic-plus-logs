# Web front (`web/`)

Vite 8 + React 19, TypeScript strict with `verbatimModuleSyntax`. Spec: `docs/superpowers/specs/2026-09-16-web-front-design.md` (screens, data flow, radar geometry, error handling). Built output `web/dist` is embedded into the Bun binary by `src/web-assets.ts`; the fixed asset names (`assets/app.js`, `assets/app.css`) are imported verbatim there — do not change `vite.config.ts` output names without updating that file.

## Rules

- **Types only from `src/`**: `import type { … } from "@shared/…"` via `web/src/types.ts` (re-export hub — add new shared types there). Runtime exception: `src/wow/classes.ts` (class names + colours). Anything else runtime from `src/` breaks the Vite build or drags Bun-only code into the browser. `web/src/lib/admin.ts`'s `AUDIT_KIND_OF` is a deliberate duplicate of `src/hosted/audit.ts`'s `ACTION_KIND` — the types-only rule means the front cannot import the runtime map, so it re-declares it (TypeScript catches a missing `AuditAction` key since the type comes from `@shared/…`; keep the two in sync by hand when an action is added).
- **No new runtime dependencies**: only `react` and `react-dom`. No router (screen = derived from tabs/history state in `App.tsx`), no state library, no CSS framework, no component library, no icon package.
- **View models are pure and tested** (`web/src/lib/*.ts` + sibling `*.test.ts`): every non-trivial transformation of `LookupPayload` into something displayable lives there — `verdict.ts` (axis order/labels, confidence colours), `axes.ts` (`AxisRowModel`; `axisInfo`/`axisWeightLabel` turn `GET /api/docs?lang=` into the "What's measured" callout text and weight line — nothing about weights or sub-signals is hard-coded in the front; `web/src/docs.tsx` `DocsProvider`/`useDocs` fetches it once per page load and again whenever the UI locale changes, keeping the previous language's docs up while the next ones load), `radar.ts`, `tiles.ts`, `runs.ts`, `deepdive.ts` (panel model, cost estimate), `compare.ts`, `history.ts`, `keyLevel.ts`, `format.ts`, `session.ts` (user menu / quota line), `help.ts` (`/help` view models: `anchorOf`, `toc`, `curveTable`, `curvePath`, `roleWeights`, `axisIsInformational`, `fmtThresholds`, `faqEntries`, `axisNote`), `hostedMode.ts` (controls, `pageOf`/`Page` for `/settings`, `/privacy` and `/help`, `proposalMode`, `adminAccess`, `accountAccess`, `deniedNotice`/`signInNote` for the four sign-in refusals), `account.ts` (issue #11: `clientCard(t, …)` — the WCL-client card's state/status/dot from `OwnClientView`, `canDelete`/`DELETE_WORD` for the typed-word confirmation, `storedDataText(t)`), `quota.ts` (labels, tooltips, 429 bodies and their toast message `quotaOrBudgetMessage(t, failure)`), `regions.ts` (the front's own copy of `src/wow/regions.ts`'s values: `REGIONS`, `isRegion`, `regionLabel`, `effectiveRegion`), `header.ts` (the two chips inside the search field: `regionMenu`/`specMenu`/`OTHER_SPEC`, `regionChipLabel`/`specChipLabel`; the EN / FR chip's `localeMenu`), `admin.ts` (budget gauge, top consumers, hourly bars, proposal cards/diff rows, decided lines, user/invite rows incl. `bannedAt`/`ownClient`, instance panel, `auditRow`/`auditDetail` for the Audit section incl. `account_delete`/`wcl_client_set`/`wcl_client_remove`/`user_ban`/`user_unban`). Components (`web/src/components/*.tsx`) stay thin: map a model to markup, hold local UI state only. Tests must not import React or the DOM (they run under `bun test` from the repo root). The registry `src/evaluation/docs.ts` must be updated with any new sub-signal — `test/evaluation/docs.test.ts` enforces it.
- **`web/src/lib/live/`** (game-integration spec: `docs/superpowers/specs/2026-09-22-game-integration-design.md`) is the Live panel's own pipeline, each file pure and tested: `codec.ts` (`STRIP`, `encodeFrame`/`decodeFrame`, `encodeCells`/`decodeCells`, `chunkRoster` — the strip contract shared byte-for-byte with the addon's `addon/bmpl/encode.lua`, pinned by `addon/bmpl/tests/vectors.txt`), `scan.ts` (reads a captured video frame's pixels into cells), `roster.ts` (`parseRoster`, `RosterAssembler`, `sortApplicants`/`filterApplicants`, the `RosterPlayer`/`Roster`/`CachedVerdict` types), `panel.ts` (`panelView`, `autoQueue`, `verdictScope` — the (key level, region) pair a cached verdict belongs to, which `App.tsx` uses to empty the verdict map when the member moves their key — and the sort/class `ChipMenu` rows), `useWowCapture.ts` (the capture hook: `getDisplayMedia`, the scan loop, `liveState` deriving the chip's off/waiting/live/reconnect/error states). Consumed by `LiveChip.tsx` (header chip + connect dialog) and `LivePanel.tsx` (the roster view), both thin per the rule above.
- **Tokens** from `web/src/styles/tokens.css` (`--bg --card --inset --border --text --muted --faint --link --green --yellow --warn --red --orange --button --mono --radius --radius-lg` …). Never a raw hex in a component or in `app.css`; if a new value is genuinely needed, add a token with a comment saying where it came from. `--discord` is the only brand colour, used on the sign-in button only.
- **English and French, from the dictionaries.** Copy is product text: short, factual, no exclamation marks. See "Strings and locales" below.
- **`App.tsx` owns the payload cache** (`Map<key, LookupPayload>`), the active tab (`activeKey` + `activeKeyRef` to avoid stale closures), `reloadActive` (clear cache entry + refetch after anything that changes a stored result: deep-dive, table edit), and the deep-dive callbacks passed down as `DeepdiveActions` (`Detail.tsx`). Keep server-truth flows server-driven: the watcher toggle reflects the SSE `status` event, history order comes from `GET /api/history`.
- **`api.ts`** is the single fetch wrapper; every call returns `ApiResult<T>` (`{ ok: true, … } | { ok: false, error, quota? }`, `quota` only from a hosted 429 `error: "quota"` body). Handle `ok: false` with a toast (`Toast.tsx`), never with `alert()`.
- **SSE**: one `EventSource("/api/events")` via `useSse` for the app lifetime; reconnect is the browser's job, the header shows the disconnected state.
- **Wowhead tooltips**: `web/index.html` loads `https://wow.zamimg.com/js/tooltips.js`; the `whTooltips` config lives in `web/public/wh-config.js` (served as `/wh-config.js`, embedded as the fourth asset alongside `index.html`/`app.js`/`app.css` — see `src/web-assets.ts`, `src/web-static.ts`), as an external script rather than an inline one so the hosted CSP needs no `'unsafe-inline'` for scripts. Render spell names through `SpellLink.tsx` (`useWowheadRefresh` calls `$WowheadPower.refreshLinks()` after mount). Any new external origin must be justified — the hosted CSP (`src/server/security.ts`) allows `wow.zamimg.com` (scripts, styles, images) and `nether.wowhead.com` (connect) besides self.
- **Settings** ("your key", legend state) come from `SettingsProvider` (`web/src/settings.tsx`, logic in `lib/settings.ts`): localStorage keys `bmpl.yourKey` / `bmpl.legendOpen` locally, `GET/PUT /api/settings` when hosted; always with a working fallback.
- **Hosted mode in the front**: everything hosted-only is decided by `uiControls(status)` / `proposalMode(status, me)`; local mode must stay pixel-identical (new classes only: `.signin*`, `.user-menu`/`.menu*`, `.avatar`, `.dot*`, `.btn-discord`, `.admin-*`, `.gauge*`, `.diff*`, `.confirm`). `/admin` renders inside `Main` (header without the search form); `adminAccess(status, me)` decides page vs `Forbidden`. `RunDeepDive` is the one component that loads data on its own (`GET /api/defensives` for the member's proposals, 0 WCL pts) — keyed on the analysis object so a patch → `reloadActive` re-reads it.
- **Radar**: `viewBox="-70 -5 440 310"`, centre (150,150), R = 110, axis order survival, utility, throughput, consistency, preparation, experience at −90°, −30°, 30°, 90°, 150°, 210°; a `null` axis is drawn hollow at the centre, never as 0.

## Strings and locales

Design: `docs/superpowers/specs/2026-09-21-french-locale-design.md`. Two UI languages, English and French, picked up
front (no library): `web/src/i18n/en.ts` is the source of truth, nested by area (`header`, `tabs`, `verdict`, `axes`,
`tiles`, `runs`, `deepdive`, `compare`, `account`, `admin`, `help`, `errors`, `common`); `fr.ts` is typed
`Mirror<typeof en>` (`web/src/i18n/t.ts`) so a missing or extra key is a `tsc` error, not a runtime gap.
`web/src/i18n/i18n.test.ts` is the parity test: same leaf keys, same `{param}`/`{count, plural, one {…} other {…}}`
placeholders in both files, no empty message. `t(key, params?)` (`makeT`) looks a dotted key up and formats it —
a missing key returns the key itself rather than throwing. `useT()` (`web/src/locale.tsx`, `LocaleProvider`) gives
components `{ t, locale, setLocale }`; `effectiveLocale`/`detectLocale` (`web/src/lib/locale.ts`) decide English vs.
French from the remembered choice (`Settings.locale`, `bmpl.locale` locally / `user_settings.locale` hosted) or the
browser otherwise — the only place that rule lives.

Never write a UI literal in a component: every string a component renders comes from `t`, either directly or through
a pure view model. The rule from "View models are pure and tested" above extends to locale: a view model that
produces prose takes `t: T` as its first parameter (`clientCard(t, …)`, `axisInfo(t, docs)`, `evidenceText(t, locale,
e)`, `specMenu(t, payload, current)` …); its test binds `tEn = t(en, "en")` from `web/src/i18n/t.ts` so existing English
assertions read unchanged, plus one French assertion per function where the wording is not a straight word swap
(plurals, word order). A view model that only computes numbers or keys (no prose) does not take `t`. `Around.tsx`
splits a translated message around its `{name}` placeholders so a link, a styled `code` span or an untranslated
site-literal word (a spell name, a Discord handle) can be embedded without flattening it to text.

Register and glossary (which WoW terms stay English in French copy, franglais, "tu") are decided once in the spec's
"Decisions" table — read it there rather than re-deriving it per string; `immunité`, `défensif`/`defensive` and
`override` are accepted French/loanwords in the UI, not gaps to fix.

## Dev loop

```
just serve --no-open      # Bun API on :3000, straight from src/cli.ts (no build needed)
just web-dev              # Vite on :5173 with /api proxied to :3000
bun test web/src          # view-model tests only
bun run --cwd web typecheck
just build                # before testing the embedded UI through ./bmpl serve
```

The compiled binary serves whatever `web/dist` contained at `just build` time; browsers cache `assets/app.js` aggressively (fixed name) — after a rebuild, hard-reload (Ctrl+F5) and kill any older `./bmpl serve` still holding :3000 (`for p in $(pgrep -f '^\./bmpl'); do kill $p; done` — never `pkill -f "bmpl serve"`, it matches your own shell).

## Design first — Claude Design canvas

The user's standing rule: any visible UI change is mocked on the Claude Design canvas before it is coded, and the user picks between variants (A/B/C) there. The canvas artboards live at **https://claude.ai/artifact/3yUjZKgaQyHKebzyqcio5s** (pages: direction-a, iteration-2, explorations, deep-dive, axis-explainers, hosted); their source is checked in under `docs/design/canvas/` (`*.dc.html` + `canvas.json`). The admin page (issue #8) has its own artboards on the hosted page: `AdminTabs` (A), `AdminOnePage` (B, the one shipped), `AdminDashboard` (C) and `AdminDetails` (shared details — member 403, proposal card anatomy, empty queue, post-decision line, confirmations). To update: copy those files to a scratch dir, add/edit artboards (match `tokens.css` and the existing components pixel for pixel — lift values from `app.css`, never round), add a page in `canvas.json`, seed with the design skill's `seed-canvas.mjs`, republish the same artifact with `contract: "0.1.31"`, favicon 🛡️ and no `capabilities`, then copy the updated sources back into `docs/design/canvas/`. Read the artifact first if it may have been edited in the GUI. Once the user chooses, implement exactly the chosen variant.
