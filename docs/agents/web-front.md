# Web front (`web/`)

Vite 8 + React 19, TypeScript strict with `verbatimModuleSyntax`. Spec: `docs/superpowers/specs/2026-09-16-web-front-design.md` (screens, data flow, error handling; its radar and tiles are gone since the redesign). Built output `web/dist` is embedded into the Bun binary by `src/web-assets.ts`; the fixed asset names (`assets/app.js`, `assets/app.css`) are imported verbatim there — do not change `vite.config.ts` output names without updating that file.

## Rules

- **Types only from `src/`**: `import type { … } from "@shared/…"` via `web/src/types.ts` (re-export hub — add new shared types there). Runtime exception: `src/wow/classes.ts` (class names + colours). Anything else runtime from `src/` breaks the Vite build or drags Bun-only code into the browser. `web/src/lib/admin.ts`'s `AUDIT_KIND_OF` is a deliberate duplicate of `src/hosted/audit.ts`'s `ACTION_KIND` — the types-only rule means the front cannot import the runtime map, so it re-declares it (TypeScript catches a missing `AuditAction` key since the type comes from `@shared/…`; keep the two in sync by hand when an action is added).
- **No new runtime dependencies**: only `react` and `react-dom`. No router (the page is `pageOf(location.pathname)`, each page a full navigation; the profile shown derives from tabs/history state in `App.tsx`), no state library, no CSS framework, no component library, no icon package.

## Strings and locales

Design: `docs/superpowers/specs/2026-09-21-french-locale-design.md`. Two UI languages, English and French, picked up
front (no library): `web/src/i18n/en.ts` is the source of truth, nested by area (`header`, `shell`, `palette`, `home`, `landing`, `tabs`, `verdict`, `axes`,
`tiles`, `runs`, `deepdive`, `compare`, `account`, `admin`, `help`, `self`, `me`, `errors`, `common`); `fr.ts` is typed
`Mirror<typeof en>` (`web/src/i18n/t.ts`) so a missing or extra key is a `tsc` error, not a runtime gap.
`web/src/i18n/i18n.test.ts` is the parity test: same leaf keys, same `{param}`/`{count, plural, one {…} other {…}}`
placeholders in both files, no empty message. `t(key, params?)` (`makeT`) looks a dotted key up and formats it —
a missing key returns the key itself rather than throwing. `useT()` (`web/src/locale.tsx`, `LocaleProvider`) gives
components `{ t, locale, setLocale }`; `effectiveLocale`/`detectLocale` (`web/src/lib/locale.ts`) decide English vs.
French from the remembered choice (`Settings.locale`, `bmpl.locale` locally / `user_settings.locale` hosted) or the
browser otherwise — the only place that rule lives.

Never write a UI literal in a component: every string a component renders comes from `t`, either directly or through
a pure view model. The rule from "View models are pure and tested" above extends to locale: a view model that
produces prose takes `t: T` as its first parameter (`clientCard(t, …)`, `axisInfo(t, docs)`, `evidenceText(t, locale,
e)`, `specMenu(t, payload, current)` …); its test binds `tEn = t(en, "en")` from `web/src/i18n/t.ts` so existing English
assertions read unchanged, plus one French assertion per function where the wording is not a straight word swap
(plurals, word order). A view model that only computes numbers or keys (no prose) does not take `t`. `Around.tsx`
splits a translated message around its `{name}` placeholders so a link, a styled `code` span or an untranslated
site-literal word (a spell name, a Discord handle) can be embedded without flattening it to text.

Register and glossary (which WoW terms stay English in French copy, franglais, "tu") are decided once in the spec's
"Decisions" table — read it there rather than re-deriving it per string; `immunité`, `défensif`/`defensive` and
`override` are accepted French/loanwords in the UI, not gaps to fix.

## Dev loop

```
just serve --no-open      # Bun API on :3000, straight from src/cli.ts (no build needed)
just web-dev              # Vite on :5173 with /api proxied to :3000
bun test web/src          # view-model tests only
bun run --cwd web typecheck
just build                # before testing the embedded UI through ./bmpl serve
```

The compiled binary serves whatever `web/dist` contained at `just build` time; browsers cache `assets/app.js` aggressively (fixed name) — after a rebuild, hard-reload (Ctrl+F5) and kill any older `./bmpl serve` still holding :3000 (`for p in $(pgrep -f '^\./bmpl'); do kill $p; done` — never `pkill -f "bmpl serve"`, it matches your own shell).

## Page width

Every in-app page sits in the frame (`Shell`, redesign spec decision 1): `.sidebar` (248 px, at most 300 px) on the
left, `.shell-main` beside it, whose `.shell-content` column is at most 1120 px wide, or `--col` while a result or a
comparison is shown (`:has(.content-result)`: 1200 px, 1640 px in `:root:has(.content-result)`). At 1000 px and below
the sidebar stacks above the content (flex wrap: no sticky, no `100vh`). The connected home page (`HomePage`) and the
landing are outside the frame and have their own centred column. No page may scroll horizontally (spec decision 8);
phase 2 redrew the candidate profile (grids that fit their column, rows stacked into cards at 390 px), phase 3 the
owner pages and phase 4 Compare and Live; no pre-redesign view is left. The owner pages (phase 3) wrap the bento to one column under 900 px and stack the run rows into cards. `--gutter` is 0 inside
the frame.
