# What's new — implementation plan

**Goal:** members see the running version under the sidebar's account block and, through it, a side panel with the
changes since their last visit, written for players.
**Architecture:** a typed changelog in `web/src/changelog/` (en source, fr mirror), stamped by the release workflow; the
running version from `GET /api/status`; `lastSeenVersion` in the settings (hosted DB column, local `localStorage`); a
pure view model `web/src/lib/whatsNew.ts`; a thin `WhatsNewPanel` component.
**Spec:** `docs/superpowers/specs/2026-10-14-whats-new-design.md`. **Mockup:** canvas
https://claude.ai/artifact/2pSkoa1YtAww5AHhWepGw8, artboard "Retenu" (`docs/design/whats-new/Retenu.dc.html`).

## Global Constraints (from the spec, verbatim where it names a rule)

- "Claude writes the entries." Every pull request with a user-visible change adds its entry, in English and French, in
  the same change.
- Source: `web/src/changelog/en.ts` and `fr.ts`; `fr` mirrors `en`: same versions, same number of items per version.
- Entries accumulate under `"next"`. Plain player language, one sentence each, no internal names, at most about five
  items per version.
- `release.yml`, in the bump commit, renames the `"next"` entry of both files to the new version with today's date. It
  refuses to run when `"next"` is missing or empty in either file.
- `GET /api/status` gains `version`, the `package.json` version.
- Hosted: `user_settings.lastSeenVersion` through `GET/PUT /api/settings`. Local: `localStorage` key
  `bmpl.lastSeenVersion`. No value yet: the current version is written silently; nothing is "new" on a first visit.
- Display: the version line of variant B opens the side panel of variant C. One real `<button>` under the account
  block: version in mono and muted, a separator, "What's new" / "Nouveautés", a dot (`--better`) while
  `lastSeenVersion` is older than the running version. The panel: right side, 440 px, full height, over the content,
  close button, Escape and a click outside close it, focus moves in and comes back to the button; "since your last
  visit · you use X.Y.Z"; entries grouped by version (mono version, date), newest first; "All changes" shows every
  version in the same panel. Opening it writes `lastSeenVersion`. Under 1000 px the panel takes the full width.
- Versions compare as semver, never as strings. `lastSeenVersion` newer than the running version (a rollback): no mark,
  nothing shown, value left as is.
- Colours from `tokens.css` only; UI strings in `web/src/i18n/`.

## Tasks

Each task ends with `just check`, `bun test` (web/dist absent) and one commit.

### 1. Changelog files and parity test
- Create `types.ts` and `en.ts` with three entries: `"next"` holding this feature's own line ("The version you use
  now shows under your account, with what changed since your last visit." / fr "La version que tu utilises s'affiche
  sous ton compte, avec ce qui a changé depuis ta dernière visite."), `0.10.2` (2026-10-14, the three lines of the
  mockup) and `0.10.1` (2026-10-12, the signal-names line). `fr.ts` mirrors.
- Test: same `version` list in the same order; equal `items.length` per version; every item non-empty and without
  "deep-dive" / "config" (internal words).
- Commit `feat(web): user-facing changelog files`.

### 2. `whatsNew.ts` (TDD)
- `compareVersions(a, b)`: split on `.`, numeric compare; `"next"` is never compared (filtered out before).
- `whatsNew(entries, lastSeen, running)`: drop `"next"`; `since` = entries with `lastSeen < version ≤ running`;
  `all` = entries with `version ≤ running`; `mark` = `lastSeen !== null && compareVersions(lastSeen, running) < 0`.
  `lastSeen` null → `mark: false`, `since: []`. Rollback (`lastSeen > running`) → `mark: false`, `since: []`.
- Tests: `0.10.2 > 0.9.9`; first visit; normal case; rollback; running version absent from the file (since still
  lists the versions in between); `"next"` never returned.
- Commit `feat(web): what's new view model`.

### 3. `/api/status` version
- Both branches of the handler add `version: pkg.version` (the import `/api/health` already uses).
- Test in the existing status test: `version` equals `package.json`'s.
- Commit `feat(server): running version in /api/status`.

### 4. `lastSeenVersion` in the settings
- Schema: add `last_seen_version` to `SETTINGS_COLUMNS` (migrated in place), select/upsert it, map to
  `lastSeenVersion` (null default).
- `SETTINGS_BODY`: `lastSeenVersion: opt(nullable(str({ max: 20, pattern: /^\d+\.\d+\.\d+$/ })))`;
  `parseSettingsPatch` copies it; the "Nothing to update" message lists it.
- Front `settings.ts`: field, default null, local read/write under `bmpl.lastSeenVersion` (try/catch like the others).
- Tests: DB round trip and migration of an old table; validation refuses `"abc"`; local storage round trip.
- Commit `feat: lastSeenVersion setting`.

### 5. Release stamp
- `scripts/changelog-stamp.ts <version> <date>`: in both files, replace the object whose `version: "next"` with
  `version: "<version>", date: "<date>"`. No new `"next"` is inserted: the next user-visible change adds one, and the
  parity test accepts its absence. Exit 1 with a message when either file has no `"next"` or an empty one.
- `release.yml`, step "Bump package.json": run `bun scripts/changelog-stamp.ts "$NEXT" "$(date -u +%F)"` before the
  version `sed`; `git commit -am` already takes both files.
- Test the script on temp copies: stamped output, refusal on a missing and an empty `"next"`.
- Commit `ci(release): stamp the changelog's next entry`.

### 6. Canvas-exact UI
- `WhatsNewButton` (in the sidebar, under the account block): `<button type="button" class="wn-line"
  aria-expanded aria-controls="whats-new">` with `<span class="mono muted">v{version}</span>`, the separator, the
  label, `<span class="wn-dot">` when `mark`.
- `WhatsNewPanel`: `<section id="whats-new" role="dialog" aria-modal="true" aria-labelledby>` 440 px on the right,
  full height, scrim behind, close `<button aria-label>`, Escape, click on the scrim; focus to the close button on
  open, back to the line on close. Body: title, the "since your last visit · you use X.Y.Z" line, `since` grouped
  (version mono + date via `Intl.DateTimeFormat(locale)`), "All changes" switches to `all`. Opening calls
  `settings.update({ lastSeenVersion: running })` (local: localStorage) once per open.
- First visit: on boot, when `lastSeenVersion` is null and the running version is known, write it without opening.
- CSS: values lifted from `Retenu.dc.html`, mapped to tokens (`--card` panel, `--border-2`, `--better` dot,
  `--label` muted); under 1000 px `.wn-panel { width: 100% }`.
- i18n: `whatsNew.label` "What's new" / "Nouveautés", `whatsNew.since` "since your last visit · you use {version}" /
  "depuis ta dernière visite · tu utilises la {version}", `whatsNew.all` "All changes" / "Tout l'historique",
  `whatsNew.close` "Close" / "Fermer", `whatsNew.empty` "Nothing new since your last visit." / "Rien de nouveau
  depuis ta dernière visite."
- Commit `feat(web): what's new line and side panel`.

  `fr.ts`"; `docs/agents/web-front.md` (view model, components); `docs/agents/workflow.md` (release step);
  `deploy/README.md` § 9 (the release refuses an empty `"next"`); the spec's status line "implemented <date>".
- Commit `docs: what's new implemented`.
